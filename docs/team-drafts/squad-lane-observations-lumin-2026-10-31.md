# Squad handoff proposal — contributor observations from Lumin

2026-10-31 America/Phoenix. Proposal author Verus; artifact introduced7264d98, inspected unchanged at PR34head018e832. Lumin helped formulate the shared register/status workflow with Tracey. These are contributor observations, not final independent clearance; Aster is the suggested non-author outside the Verus–Libra pair to review the proposal independently.

The register/claims/peer-lane split is useful. Preserve one canonical event/evidence source, with references from other records instead of independently maintained facts.

1. **Merge permission is distinct from independent review.** Option1 requests standing merge authority but says review happens before a code merge. ALL-work review applies to coordination metadata too. Standing authority, if Tracey grants it, can remove repeated merge permission requests; it cannot silently waive outside-pair non-author review of lane updates. Otherwise name a separate review-policy change for explicit decision. Do not present non-executable metadata as exempt from the agreed standard.
2. **Prefer published coordination visibility without an immediate merge exception.** A dedicated pushed coordination branch can make records readable before main merge; peers must read its exact current revision, and writers reconcile before pushing. It still needs reviewed changes and controlled ownership; branch publication is not acceptance. Whether to use that branch or scoped standing merge authority is Tracey's choice. Neither is enacted by this observation.
3. **A status must identify the evidence and its attester.** The person actually bridging an assignment attests sent; the assignee attests accepted and returned; the reviewer records findings. A lead can publish a pointer to that event with attribution, not impersonate the assignee. GitHub account reuse means a label is attribution rather than cryptographic proof of a distinct mind. Record actor, timestamp, event ID, input revision and evidence link. Keep own-lane acknowledgment as the authoritative statement with the register pointing to it, or select a different canonical event source explicitly.
4. **Returned/reviewed/consolidated are not approval.** Pin returned output to a commit/hash and verify access; a SHA string alone is not artifact verification. Reviewed records a verdict (clearance, changes requested, inconclusive), reviewer and exact output revision. Consolidated points to the new revision and its required next review; it cannot be terminal clearance when material changes remain. Administrative closure of a handoff and approval of its deliverable are separate dimensions.
5. **Append-only does not mean latest arbitrary line wins.** A stale or unrelated event must not regress another revision's status. Include predecessor/event or expected prior state, authoritative actor for each event, revised-scope handoff, and supersession links for competing assignments. Document how to reconcile concurrent appends while retaining every prior event. No automated enforcement is claimed. Do not rewrite shared history or force-push merely to append coordination.
6. **Publish referenced inputs as well as pointers.** A local Downloads brief is not accessible to Libra. Attach through the authorized bridge or publish appropriate content on a reviewed branch and pin it. Keep secrets, private suite payloads and raw adversarial results out of public records. Register only opaque suite metadata and approved reference links.

Suggested minimal first version: assignment block plus append-only evidence-linked events, clear attestation/transition rules, current revision pointers, and a published-branch read convention. Avoid introducing automation or another approval engine. The existing claims board remains the authority for edit ownership; the register does not silently release broad claims. No live squad lane or working-parameter amendment was created by these observations.
